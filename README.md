## Лабораторна робота № 8: Робота з REST API через Fetch

- **Сторінка застосунку:** `api.html` (скрипт `api.js`, стилі `api.css`)
- **Додаткова функція за варіантом:** А – Пагінація («Показати ще»)

### Картка використаного API
- **Назва сервісу:** Nager.Date API
- **Базова адреса (Base URL):** `https://date.nager.at/api/v3/PublicHolidays`
- **Приклад повного запиту:** `https://date.nager.at/api/v3/PublicHolidays/2026/UA`
- **Ключові поля JSON-відповіді:** `date` (дата свята), `localName` (місцева назва), `name` (міжнародна назва), `countryCode` (код країни).
- **Як сервіс повідомляє про порожній результат (`empty`):** повертає статус 404 Not Found для невідомого коду країни.
- **Чому `fetch()` не відхиляє `Promise` при статусі `404` або `500`:** Оскільки сервер прийняв запит і надіслав коректну HTTP-відповідь, на мережевому рівні обмін відбувся успішно. Для перевірки успішності статусу (200–299) необхідно вручну перевіряти властивість `response.ok` і викидати помилку через `throw`.

- керування станом списку, фільтрів та пошуку за допомогою хука `useState` (з дотриманням імутабельності);

  ### Лабораторна робота № 11: Створення серверної частини на Node.js та Express

- **Підпроєкт:** `lr11-server/` (запуск: `cd lr11-server`, `npm install`, `npm run dev`)
- **Варіант №:** 18
- **Параметри варіанта:**
  - **Колекція (шлях API):** `/api/cars`
  - **Поля запису:** `brand` (рядок), `model` (рядок), `year` (число)
  - **Порт:** `3018`
  - **Тип логу:** 2 (час ISO + метод + URL + статус-код)

### Реалізована функціональність
- Налаштування маршрутизації з параметрами шляху (`req.params`) та рядка запиту (`req.query`);
- Приймання та валідація JSON-даних (`req.body`) з перевіркою типів полів;
- Власне middleware для логування запитів у форматі типу 2;
- Роздача статичних файлів портфоліо з ЛР №2–4 через `express.static`;
- Централізована обробка помилок (404 та 500) з коректними HTTP-статус-кодами.

### Маршрути API
- `GET /` — головна сторінка портфоліо (статика);
- `GET /api/cars` — список автомобілів (з підтримкою пошуку `?q=` за полем `brand`);
- `GET /api/cars/:id` — отримання одного автомобіля за ID;
- `POST /api/cars` — створення нового запису (з валідацією `brand`, `model`, `year`);
- `GET /api/error` — тестовий маршрут для виклику помилки 500.

### Як запустити локально
```bash
cd lr11-server
npm install
npm run dev
```
